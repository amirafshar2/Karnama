# روش تست جمعی کارنما (PROMPT3)

## حالت QA
- فقط در محیط Development و با `Qa__Enabled=true` (در غیر این صورت `StartupGuard` برنامه را متوقف می‌کند).
- ساعت برنامه (`QaClock`) جلو می‌رود تا «یک روز کاری» در چند دقیقه اجرا شود؛ اعتبار توکن‌ها هم با همین ساعت سنجیده می‌شود.
- مسیرهای `/api/v1/qa/*` فقط از خود سرور (loopback) جواب می‌دهند: ساعت، ورود به‌جای هر نفر، اجرای کارهای زمان‌بندی‌شده، ساخت جمعیت، و ۹ «ثابت» دیتابیس.

## جمعیت
۸۱ نفر ساختگی (شماره‌های ۰۹۹۱…): ۲ مالک، مدیر، ۸ تدوینگر، ۵ عکاس/نویسنده، ۳ AI، ۴ میدانی، ۵ بازاریاب، ۲ نویسنده، تبلت کیوسک و ۵۰ مشتری (۱۰ تا با پکیج رو به پایان) + ۲ بازدیدکننده‌ی ناشناس = ۸۳.

## اجرا
```bash
bash tests/qa/qa-api.sh 5091 karnama_qa_full            # API جدا با دیتابیس تازه
QA_DB=karnama_qa_full QA_API=http://localhost:5091 node tests/qa/run.mjs   # همه‌ی سناریوها
node tests/qa/run.mjs S03 S07                            # فقط چند سناریو
node tests/qa/coverage.mjs                               # ساخت docs/qa/COVERAGE.md
bash tests/qa/qa-up.sh && node tests/qa/crowd.mjs        # Q2: ۸۳ نفر همزمان + ۵ مرورگر (CROWD_TICK_MS، CROWD_BROWSERS)
node tests/qa/crowd-report.mjs                           # ساخت docs/qa/CROWD_RUN.md
```
گزارش هر اجرا: `tests/qa/reports/run-*.json` (در گیت نیست).
