## ۲. سناریوها (همه، با مسیر خوب + خطا + لغو)

> فهرست کامل در `docs/qa/COVERAGE.md` با ارجاع به بخش پرامپت. این حداقل است.

**یک روز کاری کامل (شبیه‌سازی‌شده با ساعت QA):**
1. **ورود صبح:**
   - کارمندها: اینترنت دفتر + QR کیوسک (یکی‌دو نفر با دستگاه اثر انگشت شبیه‌سازی‌شده ADMS)
   - ۲ نفر **دیر** (تأخیر)، ۱ نفر **نمی‌آید** (غیبت اعلام‌نشده → دلیل → تأیید/رد)
   - ۱ نفر از **خانه** تلاش می‌کند (باید «نیازمند بررسی» شود)
   - ۱ فیلمبردار با **مکان جعلی** (باید «نیازمند بررسی» شود)
2. **سفارش‌ها:**
   - مشتری‌ها از کاتالوگ سفارش می‌دهند (فرم‌های دینامیک)
   - ادمین می‌پذیرد و می‌سپارد (پیشنهاد خودکار کارگر)
   - کارگرها تایمر می‌زنند، مکث، کار دوم (مکث خودکار اولی)
   - آپلود قابل ادامه با **قطع نت وسط آپلود**
   - ارسال برای بازبینی → رد با یادداشت → اصلاح → تأیید → تأیید مشتری / «اصلاح لازم است»
   - PublishJob: آژانس منتشر می‌کند؛ یادآوری سر ساعت برای مشتری با پیج دست خودش → «منتشر کردم» → یکی **Overdue**
3. **ربات تلگرام (Mock Gateway):**
   - فیلمبردار ویدیو می‌فرستد → ساعت آپلود ثبت می‌شود → کپی برای ادمین → ادمین در «صندوق فایل‌ها» به تدوینگر می‌سپارد → تحویل در تلگرام (Mock)
   - کاربر وصل‌نشده فایل بفرستد → رد
4. **تجهیزات:**
   - تحویل دوربین با عکس → تأیید کارگر
   - انتقال مستقیم بین دو کارگر
   - دیر شدن برگشت (ساعت QA جلو) → هشدار
   - برگشت با گزارش خرابی
5. **CRM:**
   - ادمین ۱۰۰ سرنخ را چرخشی پخش می‌کند
   - بازاریاب‌ها تماس می‌گیرند → «نتیجه‌ی تماس» → پیگیری
   - ۳ برد → تبدیل به مشتری + پکیج
   - بازاریاب A سعی می‌کند سرنخ B را باز کند → 404
6. **پکیج‌ها:**
   - ادمین پکیج جدید با تخفیف زمان‌دار و توضیحات کامل (ویرایشگر) می‌سازد
   - تخصیص FullAccess با رمز → دیدن رمز با OTP (Audit)
   - ساعت QA جلو → پیام‌های ۷/۳/۱ روز و روز پایان (هر کدام **فقط یک بار**)
   - تمام شدن سهمیه
   - درخواست تمدید
7. **مرخصی:**
   - درخواست روزانه و ساعتی → تأیید/رد
   - ادمین برای کارگر ماموریت ثبت می‌کند
   - مانده‌ی مرخصی درست
8. **گفتگو:**
   - مدیر ↔ کارگرها، گروه تدوین
   - پیام صوتی کوتاه، عکس، «درباره‌ی این کار»
   - مشتری ↔ ادمین
9. **عصر:**
   - خروج (یکی فراموش می‌کند → هشدار → «نیازمند بررسی»)
   - درخواست اصلاح ساعت → تأیید
10. **گزارش و امتیاز:**
    - گزارش بازه‌ای هر کارگر و کل تیم (Excel و PDF باز و چک شوند)
    - امتیازها و «چرا این امتیاز»
    - کار عقب‌افتاده به‌خاطر مشتری روی امتیاز اثر نگذارد
11. **سایت عمومی:**
    - بازدیدکننده صفحه‌ی اصلی، نمونه‌کار و بلاگ را می‌بیند → فرم مشاوره → سرنخ در CRM
    - نویسنده پست با عکس وسط متن و مارک‌داون می‌نویسد → بازبینی → انتشار زمان‌بندی‌شده
12. **ادمین:**
    - CRUD همه‌ی موجودیت‌ها
    - نقش جدید با مجوزهای دلخواه → اعمال لایو روی کاربر
    - افزودن زبان انگلیسی و تغییر به LTR
    - تغییر رنگ برند
    - نصب خالی → `/setup` → دستیار
13. **دوربین** (شبیه‌ساز RTSP مثل یک ویدیوی تکراری در MediaMTX):
    - نمای اسنپ‌شات → زنده → قطع بعد از بی‌حرکتی
    - کاربر بدون مجوز → رد
14. **راهنما:**
    - تور اول هر نقش
    - دکمه‌ی «؟»
    - هیچ فیلدی بدون توضیح (تست خودکار helperText)

**ثابت‌های دیتابیس بعد از هر اجرا:**
- هر کاربر ≤ ۱ تایمر باز و ≤ ۱ شیفت باز
- هر تجهیز ≤ ۱ تحویل فعال
- سهمیه ≥ ۰
- هر QR کیوسک ≤ ۱ استفاده
- هیچ پیام انقضای تکراری
- Outbox گیرکرده = ۰
- هر `MediaAsset` فرستنده‌ی وصل‌شده دارد
- مجموع ساعت‌ها = مجموع رویدادها

## ۴. گروه دوم — ۱۰۰۰ کاربر

- **ترکیب:**
  - ۴۰ Owner/مدیر
  - ۳۲۰ کارمند (۲۵٪ بیرون)
  - ۶۰ بازاریاب
  - ۲۰ نویسنده
  - ۵۰۰ مشتری
  - ۶۰ بازدیدکننده‌ی عمومی
- **Seed حجیم:** ۲۰٬۰۰۰ سفارش تاریخی، ۵۰٬۰۰۰ رویداد زمان، ۳٬۰۰۰ سرنخ، ۴۰۰ تجهیز، ۲۰۰ پست بلاگ، ۵۰ نمونه‌کار.
- **اجرا:**
  - ۹۵۰ کاربر k6 (HTTP + SignalR) + ۲۰ تا ۵۰ مرورگر Playwright + ۲ امولاتور اندروید
  - **۳۰ دقیقه** با شیب ورود صبح (۱۰ دقیقه‌ی اول بیشتر ورودها)
  - ۱۵ دقیقه‌ی ثابت
  - ۵ دقیقه «طوفان»: همه‌ی مشتری‌ها همزمان پورتال را باز می‌کنند
- **معیار:**
  - p95 API < 300ms، خطا < ۰.۵٪
  - تأخیر لایو p95 < ۲s
  - INP مرورگرها < 200ms
  - ثابت‌های دیتابیس سالم
  - بدون نشت حافظه
