# بررسی امنیتی N7 (CRM و بازاریاب‌ها) — ۴ آبان ۱۴۰۵

| موضوع | نتیجه |
|---|---|
| دید سرنخ‌ها | `crm.leads:Own` فقط سرنخ‌های خودش؛ سرنخ بازاریاب دیگر در خواندن/ویرایش/تماس/تبدیل → ۴۰۴ و در کانبان دیده نمی‌شود (تست IDOR)؛ کارگر و مشتری ۴۰۳ (تست) |
| شماره‌ی تکراری | ثبت دوباره‌ی یک شماره ۴۰۹؛ اگر سرنخ مال همکار دیگری باشد نامش فاش نمی‌شود (تست)؛ فقط مدیر فروش می‌تواند با «Force» تکراری بسازد |
| سپردن | فقط `crm.assign`؛ گیرنده باید بازاریاب باشد؛ هر انتقال در تاریخچه (تست)؛ چرخشی با نوبت ذخیره‌شده (تست) |
| تبدیل به مشتری | فقط سرنخ‌های قابل‌دید؛ شماره‌ی موجود به همان مشتری وصل می‌شود (مشتری تکراری ساخته نمی‌شود)؛ دوباره زدن = همان مشتری (تست)؛ Audit |
| ورودی بیرونی | فرم سایت: Honeypot، محدودیت IP، یک درخواست در ساعت برای هر شماره؛ پیام دوباره به سرنخ باز همان شماره اضافه می‌شود. ربات: فقط از کاربران وصل‌نشده، شماره فقط از متن خود شخص یا دکمه‌ی «ارسال شماره» که مال خودش باشد (`contact.user_id == from.id`) |
| یادآوری پیگیری | هر زمان پیگیری یک بار (تست)؛ به مالک سرنخ، یا اگر مالک ندارد به سپارنده‌ها |
| تماس | فقط `tel:`؛ مکالمه ضبط نمی‌شود؛ مدت از رفت‌وبرگشت به اپ فقط پیشنهاد است |
| مهاجرت داده | سرنخ‌های N10 روی مراحل پیش‌فرض نگاشت شدند؛ نقش‌های `leads.manage` به `crm.leads:All` + `crm.assign` + `crm.pipeline.manage` تبدیل شدند (روی دیتابیس قدیمی امتحان شد) |

یافته‌ی High/Critical: **ندارد**.
