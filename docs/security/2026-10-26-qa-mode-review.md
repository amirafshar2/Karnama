# بازبینی امنیتی — حالت QA و رفع یافته‌های دور ۱ (۵ آبان ۱۴۰۵)

| موضوع | بررسی | نتیجه |
|---|---|---|
| حالت QA در تولید | `Qa:Enabled` بیرون از Development → `StartupGuard` برنامه را بالا نمی‌آورد؛ تست `StartupGuard` | ✅ |
| مسیرهای `/qa` | فقط وقتی حالت QA روشن است map می‌شوند و فیلتر loopback دارند (IP واقعی اتصال، نه X-Forwarded-For) | ✅ |
| ورود بدون رمز (`login-as`) | فقط در حالت QA؛ در ممیزی `qa.login` ثبت می‌شود | ✅ |
| ساعت جابه‌جا | `TimeProvider.System` در حالت عادی؛ `QaClock` فقط در حالت QA ثبت می‌شود | ✅ |
| بالا رفتن سطح نقش | غیرمالک فقط نقشی را می‌سازد/عوض می‌کند که همه‌ی دسترسی‌هایش را خودش دارد؛ نقش خودش را نمی‌تواند عوض کند | ✅ |
| لغو فوری دسترسی | `SecurityStamp` با تغییر نقش، دسترسی‌های نقش، حذف/بازیابی، غیرفعال‌سازی عوض می‌شود؛ توکن قدیمی در حداکثر ۳۰ ثانیه (کش) ۴۰۱ می‌گیرد | ✅ |
| حریم خصوصی گفتگو | تنظیم «گفتگوی مشتری» در سرور اعمال می‌شود، نه فقط در UI | ✅ |
| سپردن فایل | فقط به کارمند؛ مشتری فقط از مسیر `toClient` | ✅ |
| خطای همزمانی | ۲۳۵۰۵ → ۴۰۹ ProblemDetails بدون جزئیات دیتابیس | ✅ |
| مدیریت زبان | فقط `languages.manage`؛ کد زبان فقط ۲ تا ۱۰ حرف کوچک لاتین یا خط تیره (در Domain)؛ زبان پیش‌فرض خاموش نمی‌شود | ✅ |
| زنگوله | `before` فقط تاریخ است و همان فیلتر کاربر جاری اعمال می‌شود (IDOR ندارد) | ✅ |
| رمزهای اسکریپت QA | رمز آزمایشی درگاه تلگرام فقط مقدار پیش‌فرض اسکریپت محلی است، در کد برنامه نیست | ✅ |
