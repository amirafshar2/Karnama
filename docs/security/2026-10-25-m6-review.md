# بررسی امنیتی M6 (اعلان‌ها، انتشار، پیام مشتری) — ۳ آبان ۱۴۰۵

| موضوع | نتیجه |
|---|---|
| وبهوک بله | مسیر با رمز مخفی (`Messengers__BaleWebhookSecret`)، مقایسه‌ی زمان‌ثابت؛ رمز اشتباه = ۴۰۴ (تست)؛ بدنه حداکثر ۶۴KB |
| به‌روزرسانی‌های تلگرام از Gateway | امضای HMAC-SHA256 روی «زمان.بدنه» + پنجره‌ی ۵ دقیقه ضد Replay (تست ۴۰۱ برای امضای غلط و قدیمی) |
| تکرار یک Update | جدول `bot_updates` با کلید (پیام‌رسان، شناسه) — بار دوم کاری نمی‌کند (تست) |
| اتصال ربات | فقط با کد یک‌بارمصرف ۱۰ دقیقه‌ای که هش‌شده ذخیره می‌شود؛ هرگز با شماره تلفن؛ کد دوباره کار نمی‌کند (تست)؛ `/stop` از خود چت قطع می‌کند |
| اعلان دیگران | فهرست، خواندن و رویداد لایو اعلان فقط برای صاحبش (گروه `user:{id}`؛ `changes` هم فیلتر شد) |
| لینک داخل اعلان | فقط مسیر داخلی (`/…`)؛ بخش کلاینت هم دوباره بررسی می‌کند (جلوگیری از Open Redirect) |
| اعلان تکراری | کلید رویداد یکتا برای هر نفر (`notifications (UserId, EventKey)`) و کلید یکتای Outbox — Job تکراری دوبار خبر نمی‌دهد (تست) |
| ارسال Outbox | گرفتن دسته با `UPDATE … FOR UPDATE SKIP LOCKED … RETURNING` (Lease پنج‌دقیقه‌ای)؛ تراکنش هنگام تماس با سرویس بیرونی باز نمی‌ماند؛ متن پیام در لاگ نوشته نمی‌شود |
| پیامک | فقط برای اعلان «مهم» و فقط اگر کاربر روشن گذاشته باشد (هزینه) |
| انتشار | ساختن/ویرایش/لغو فقط `orders.manage:All` (تست ۴۰۳)؛ پیج باید مال همان مشتری باشد، سفارش و فایل‌ها هم (تست ۴۲۲) |
| «منتشر کردم» مشتری | فقط پیج‌های «دست مشتری» و فقط مال خودش؛ لینک پست فقط `https` (تست `javascript:` رد شد) |
| فایل برای مشتری | فقط فایل‌های همان PublishJob برای مشتری قابل دانلود می‌شوند |
| پیام مشتری | فقط روی سفارش خودش (۴۰۴ برای سفارش دیگران)؛ سقف ۳۰ پیام در ساعت؛ فقط ادمین‌ها خبردار می‌شوند |

**باقی‌مانده (برنامه‌ریزی‌شده):** خود سرویس `Karnama.TelegramGateway` (بیرون ایران) در N5 ساخته می‌شود؛ پروتکل امضا از همین حالا ثابت است.

یافته‌ی High/Critical: **ندارد**.
