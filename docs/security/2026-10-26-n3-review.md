# بررسی امنیتی N3 (تجهیزات سپرده به کارگر) — ۴ آبان ۱۴۰۵

| موضوع | نتیجه |
|---|---|
| دید | `assets.view:Own` فقط تجهیزی که دست خودش است یا همکار برایش فرستاده؛ تجهیز دیگران با شناسه، کد اموال (QR) یا شناسه‌ی تحویل → ۴۰۴ (تست IDOR)؛ مشتری ۴۰۳ (تست) |
| تاریخچه برای کارگر | فقط تحویل‌ها و رویدادهای خودش؛ قیمت خرید فقط برای مدیر |
| تعریف و تحویل | ساخت/ویرایش/حذف فقط `assets.manage`؛ تحویل، لغو و تأیید برگشت فقط `assets.assign` (۴۰۳ تست)؛ گیرنده باید همکار فعال باشد |
| تأیید کارگر | فقط خود گیرنده «تحویل گرفتم» یا «تحویل نگرفتم» می‌زند؛ مدیر نمی‌تواند جای او تأیید کند (۴۰۳ تست) |
| همزمانی | هر تجهیز فقط یک تحویل باز: ایندکس یکتای فیلترشده `ux_asset_assignments_open` + RowVersion روی تجهیز. دو تحویل همزمان → یکی ۲۰۰ و دیگری ۴۰۹؛ درج مستقیم دوم در دیتابیس هم رد می‌شود (تست) |
| انتقال مستقیم | فقط دارنده (یا مدیر) پیشنهاد می‌دهد، فقط گیرنده‌ی نام‌برده قبول می‌کند؛ تحویل قبلی و جدید در یک تراکنش Serializable بسته و باز می‌شوند (تست) |
| عکس‌ها | فقط JPG/PNG/WebP با بررسی امضای فایل، حداکثر ۵ مگابایت، ۲۰۰ عکس برای هر تجهیز؛ بیرون از وب‌روت؛ دانلود فقط با همان قانون دید، با `nosniff` (تست) |
| تاریخچه | `asset_events` فقط افزوده می‌شود؛ تغییرهای مهم (ثبت، ویرایش با قبل/بعد، حذف، وضعیت، تحویل، برگشت، انتقال) در Audit |
| حذف | نرم (Soft delete)؛ تجهیزی که دست کسی است حذف نمی‌شود (۴۰۹ تست)؛ کد اموال حذف‌شده دوباره ساخته نمی‌شود |
| هشدارها | برگشت دیرشده روزی یک بار، گارانتی ۳۰/۷ روز مانده و تمام‌شده هر کدام یک بار، تجهیز دست همکار غیرفعال (تست بدون تکرار) |

یافته‌ی High/Critical: **ندارد**.
