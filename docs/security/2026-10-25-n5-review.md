# بررسی امنیتی N5 (Gateway تلگرام، ربات فایل‌ها، صندوق فایل‌ها) — ۳ آبان ۱۴۰۵

| موضوع | نتیجه |
|---|---|
| Webhook تلگرام (Gateway) | مسیر مخفی + هدر `X-Telegram-Bot-Api-Secret-Token`، هر دو با مقایسه‌ی زمان‌ثابت؛ اشتباه → ۴۰۴ (تست)؛ بدنه حداکثر ۱MB |
| Gateway ↔ ایران | HMAC-SHA256 روی «زمان‌مهر.بدنه»، پنجره‌ی ۵ دقیقه؛ بی‌امضا/امضای غلط/زمان قدیمی → ۴۰۱؛ همان درخواست امضاشده دو بار → ۴۰۱ (حافظه‌ی امضاها، تست)؛ امضای دو طرف یکسان (تست) |
| تکرار Update | صف دیسکی با نام `update_id` (ارسال دوباره‌ی تلگرام = یک فایل، تست)؛ در ایران `bot_updates` یکتا (تست: همان Update دو بار = یک رکورد) |
| قطعی اینترنت | صف دیسکی در Gateway (تا ۷ روز، ۲۰ هزار پیام؛ پر بودن → ۵۰۳ تا تلگرام دوباره بفرستد)؛ دستورها در Outbox ایران با تلاش دوباره و Backoff |
| متدهای تلگرام | فقط `sendMessage`، `copyMessage`، `answerCallbackQuery`، `editMessageReplyMarkup` (دو طرف چک می‌کنند؛ تست ۴۰۰ برای بقیه) |
| فرستنده‌ی ناشناس | فقط یک خط «اول حساب را وصل کنید»؛ هیچ رکوردی ساخته نمی‌شود (تست) |
| شناسایی | فقط با اتصال یک‌بارمصرف (`/start کد`)، هرگز با شماره؛ فقط چت خصوصی (گروه‌ها نادیده) |
| دکمه‌های داخل تلگرام | انتخاب کار فقط برای فرستنده‌ی همان فایل و کارهای خودش؛ «سپردن به…» فقط با `media.assign` (تست: کارگر دکمه را بزند → «اجازه ندارید») |
| فایل تکراری | `file_unique_id` یکتا برای هر پیام‌رسان (تست) |
| بایت فایل | هرگز دانلود نمی‌شود (فقط `file_id`)؛ پیش‌نمایش حداکثر ۱MB، با بررسی Magic Bytes، در پوشه‌ی خصوصی، فقط برای `media.inbox` |
| کپشن‌ها | بدون شماره‌ی تماس مشتری (تست)؛ دکمه‌ی لینک فقط با آدرس https |
| خطای تحویل | ۴۰۰/۴۰۳ تلگرام (مثلاً بلاک) = توقف بدون تکرار + وضعیت «نرسید» + اعلان مهم به سپارنده (تست) |
| رازها | توکن ربات فقط در `.env` سرور خارج؛ کلید HMAC در هر دو `.env`؛ Gateway اجرای بدون تنظیمات کامل را رد می‌کند |
| Caddy سرور خارج | فقط `/tg/*`، `/v1/*`، `/health`؛ بقیه ۴۰۴ |

یافته‌ی High/Critical: **ندارد**.
