# نسخه‌ی دمو روی Render (رایگان)

> فقط برای **نمایش به مشتری**: داده‌ی نمونه و ورود با یک کلیک برای هر نقش. برای کار واقعی آژانس نیست (`deploy/README.md` را ببینید).
> محیط برنامه `Demo` است: فقط با داده‌ی نمونه بالا می‌آید و حالت QA در آن خاموش است.

## چه چیزی ساخته می‌شود

| سرویس | چیست |
|---|---|
| `karnama-api` | API **با دیتابیس PostgreSQL داخل همان سرویس** (`Dockerfile.demo`)؛ با هر ری‌استارت دمو از نو و تمیز ساخته می‌شود. اپ اندروید مستقیم به این وصل می‌شود |
| `karnama-web` | سایت و پنل. درخواست‌های `/api` را خودش به API می‌رساند تا ورود (کوکی) روی یک آدرس بماند |

## قدم‌ها

1. کد را به GitHub پوش کن (فایل `render.yaml` در ریشه‌ی پروژه است).
2. در Render: **New → Blueprint** → مخزن را انتخاب کن → Render فایل `render.yaml` را می‌خواند.
3. Render چهار مقدار را می‌پرسد. اگر اسم سرویس‌ها آزاد باشد، آدرس‌ها این‌طور می‌شوند:

   | کلید | مقدار |
   |---|---|
   | `API_PROXY_TARGET` (سرویس web) | `https://karnama-api.onrender.com` |
   | `API_INTERNAL_BASE` (سرویس web) | `https://karnama-api.onrender.com` |
   | `NEXT_PUBLIC_HUB_BASE` (سرویس web) | `https://karnama-api.onrender.com` |
   | `Cors__AllowedOrigins__1` (سرویس api) | `https://karnama-web.onrender.com` |

   اگر Render به آخر اسم‌ها چیزی اضافه کرد (مثلاً `karnama-api-x1y2.onrender.com`)، بعد از ساخته شدن سرویس‌ها این چهار مقدار را در **Environment** هر سرویس درست کن و **Manual Deploy → Clear build cache & deploy** بزن. سایت باید دوباره ساخته شود، چون این آدرس‌ها موقع ساختن داخلش قرار می‌گیرند.
4. صبر کن تا هر سه سبز شوند. بار اول ساختن API و سایت هر کدام چند دقیقه طول می‌کشد.
5. باز کن: `https://karnama-web.onrender.com` → «ورود به پنل» → یکی از دکمه‌های نقش (مدیر، کارمند، مشتری…).
6. صفحه‌ی اول سایت را **دو بار** با یک دقیقه فاصله باز کن: بار اول ممکن است بدون عکس‌ها و متن‌های دمو باشد (موقع ساختن سایت هنوز API بالا نبوده)؛ سایت خودش یک دقیقه بعد تازه می‌شود.
7. آدرس سایت و API را برای Claude بفرست تا چک کند و نسخه‌ی اندروید را با آدرس API بسازد.

## نکته‌های پلن رایگان

- **خوابیدن:** بعد از حدود ۱۵ دقیقه بی‌کاری می‌خوابد و باز شدن بعدی حدود یک دقیقه طول می‌کشد. **چند دقیقه قبل از جلسه با مشتری** سایت و یک صفحه‌ی پنل را باز کن تا API هم بیدار شود.
- **بدون دیسک:** فایل‌هایی که در دمو بارگذاری می‌شوند (عکس، ویدیو، فایل کار) با هر ری‌استارت پاک می‌شوند. داده‌های نمونه، عکس‌ها و ویدیوی خود دمو داخل برنامه‌اند و می‌مانند.
- **دیتابیس داخل API است:** سرویس جدا لازم نیست و منقضی هم نمی‌شود. ولی هر بار که سرویس می‌خوابد و بیدار می‌شود، دمو با داده‌های نمونه از اول ساخته می‌شود (حدود ۲۰ ثانیه) و هر چیزی که در دمو وارد شده پاک می‌شود. برای نمایش به مشتری همین خوب است: همیشه تمیز است.
- **کارهای زمان‌بندی‌شده و ربات تلگرام** (سرویس Worker) در این دمو نیستند؛ چون Worker در پلن رایگان نیست. اعلان‌های داخل برنامه، چت و کانبان لایو کار می‌کنند.
- **دسترسی از ایران:** قبل از جلسه، یک نفر در ایران **بدون VPN** سایت را باز کند. Render شرکت آمریکایی است و ممکن است به‌خاطر تحریم باز نشود. اگر باز نشد، سراغ سرور آلمان یا ایران برو (`deploy/README.md`).

## امنیت

- همه‌ی کلیدها (`Jwt__SigningKey`، `Otp__HashKey`، `Setup__Token`، `Vault__MasterKey`) را خود Render تصادفی می‌سازد. هیچ کلیدی در مخزن نیست.
- ورود با یک کلیک فقط در محیط `Development` و `Demo` مجاز است. در `Production` برنامه اصلاً بالا نمی‌آید (`StartupGuard`).
- در دمو هیچ اطلاعات واقعی مشتری وارد نکن: هر کسی که آدرس را داشته باشد، می‌تواند با یک کلیک وارد شود.

## اپ اندروید

- با هر پوش، گیت‌هاب خودش اپ را می‌سازد (`.github/workflows/android.yml`) و در بخش **Releases** با اسم `android-latest` می‌گذارد.
- در پنل، منوی **«اپ اندروید»** (برای همه‌ی کاربرها، فقط روی سایت) دکمه‌ی دانلود مستقیم، کد QR و راهنمای نصب را دارد.
- **مخزن باید Public باشد**؛ وگرنه لینک دانلود برای مشتری کار نمی‌کند.
- کلید امضا: چهار Secret که در `Downloads\karnama-android-key\README-fa.txt` توضیح داده شده. بدون آن‌ها هم ساخته می‌شود، ولی هر نسخه‌ی تازه فقط بعد از پاک کردن نسخه‌ی قبلی نصب می‌شود.
- آدرس API اپ پیش‌فرض `https://karnama-api.onrender.com` است. اگر فرق دارد: Settings → Secrets and variables → Actions → **Variables** → `ANDROID_API_BASE`.
